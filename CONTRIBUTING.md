# Contributing

Thanks for helping make product design more rigorous, useful, and open.

## What belongs here

A contribution should improve at least one of these outcomes:

- clearer product decisions;
- more complete user journeys and states;
- more coherent and accessible systems;
- better design-to-build handoffs;
- stronger, reproducible verification;
- more reliable agent behavior.

Avoid adding trend lists, unexplained aesthetic prescriptions, unverifiable claims, copied proprietary material, or large collections without a retrieval and maintenance strategy.

## Contribution standard

For new guidance or patterns, include:

1. Context: where the guidance applies.
2. Decision: what it recommends.
3. Rationale: what user or product outcome it supports.
4. Counterexample: when it should not be used.
5. Verification: how someone can check the result.
6. Source: authoritative references where the claim depends on external facts.

Keep the core `SKILL.md` concise. Put detailed or platform-specific material in a directly linked reference file. Do not duplicate the same guidance in multiple files.

## Before opening a pull request

- Run the skill validator.
- Check links and examples.
- Confirm prompts do not encourage fabricated research or test results.
- Explain which gate and product outcome the change improves.
- Include a realistic before/after example for behavioral changes.

Use the repository pull-request template and keep each pull request focused on one reviewable outcome. Maintainer approval and passing validation are required before merge.

## Ways to participate

- Use an issue to report a reproducible problem or propose a bounded change.
- Use Discussions for questions, early ideas, design critique, and show-and-tell.
- Use a pull request for a reviewable implementation with evidence.
- See [Extending Design to Ship](docs/extending.md) for adapters, skills, framework playbooks, benchmarks, and compatible integrations.
- See [Contributors and adopters](CONTRIBUTORS.md) for recognition and showcase guidance.

Contributors retain copyright in their work and provide it under the repository's MIT license when their contribution is merged.
