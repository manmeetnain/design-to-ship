# Deliverable contract

Scale depth to the request, but preserve this order.

## 1. Direction

- Mode and scope
- Product outcome
- Audience and context
- Evidence ledger
- Assumptions and non-goals

## 2. Experience

- Jobs and journeys
- Information architecture
- State and edge-case inventory
- Content hierarchy

## 3. Design system

- Design principles
- Visual direction and rationale
- Semantic colors, typography, spacing, radius, elevation, and motion
- Components and interaction states
- Responsive and accessibility rules
- Anti-patterns for this product

## 4. Build contract

- Screen inventory
- Component map
- Data and integration needs
- Requirement-linked acceptance criteria
- Platform-specific implementation notes

## 5. Proof report

- Checks performed and evidence observed
- Rubric score by dimension when auditing
- Known gaps and risks
- Readiness verdict
- Next smallest action

Use compact tables for traceability matrices and comparisons. Use diagrams only when relationships or sequence are genuinely easier to understand visually.
