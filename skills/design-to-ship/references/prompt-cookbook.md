# Prompt cookbook

## Master prompt

```text
Use $design-to-ship in FULL mode.

Take the following product from raw requirements to a verified implementation plan:
[PASTE PRODUCT IDEA, BRIEF, PRD, LINKS, OR EXISTING FILES]

Audience: [WHO]
Platform: [WEB / IOS / ANDROID / DESKTOP]
Business outcome: [OUTCOME]
Constraints: [STACK, BRAND, TIME, ACCESSIBILITY, REGULATORY]
Existing assets: [DESIGN SYSTEM, CODE, RESEARCH, CONTENT]

Work through Intent, Structure, System, Build, and Proof. Maintain an evidence ledger using CONFIRMED, INFERRED, PROPOSED, UNKNOWN, and CONFLICTING. Give stable IDs to requirements and trace important design decisions and acceptance criteria back to them.

Make the product feel specific to its audience and purpose. Avoid generic AI styling and explain the product reason for every consequential visual or interaction choice. Include primary, alternate, loading, empty, error, permission, destructive, success, and recovery states where relevant.

Deliver the experience architecture, design direction, semantic tokens, responsive rules, component map, implementation contract, verification plan, known risks, and exactly one readiness verdict. Do not claim anything was tested unless you inspected evidence.
```

## Audit an implementation

```text
Use $design-to-ship in AUDIT mode. Compare [IMPLEMENTATION] against [REQUIREMENTS OR DESIGN]. Score every quality dimension, cite observed evidence, identify the smallest high-impact fixes, and return one readiness verdict. Do not confuse visual similarity with product correctness.
```

## Create a focused experience

```text
Use $design-to-ship in DEFINE and DESIGN modes for [FEATURE]. Preserve the current product's design system. Specify the primary journey, edge states, content hierarchy, interaction behavior, responsive adaptation, accessibility requirements, and requirement-linked acceptance criteria.
```
